# T006 verification — durable work engine

Implemented on feature/T006-durable-work, based on main 10641ce.

## Scope and acceptance

- PostgreSQL migration 0002 adds jobs, attempts, targets, immutable results and a transactional outbox.
- Idempotent submission and row-locked claims prevent duplicate visible results.
- RabbitMQ confirmed persistent publishing runs outside database transactions; failed delivery is retried with a bounded budget.
- Random leases, heartbeat renewal, cancellation and generation/tombstone checks fence stale workers.
- Authenticated owner-only APIs provide creation, latest-50 listing, cancel and bounded replay.
- Operations displays real returned job state through a no-cache server proxy and clears rows after access failure.
- Initial handler is a real bounded worker diagnostic. Document parsing/indexing remains T007.

The disposable recovery verifier stops/restarts its own RabbitMQ broker, replays
a committed unpublished job, sends duplicates, SIGKILLs its active worker process,
starts a replacement and verifies exactly one output with two attempts. It also
invalidates an in-flight generation and cancels another job, preventing output.
PostgreSQL tests cover concurrent submission/claims, old lease fencing, same-tenant
owner separation, cross-tenant access, membership revocation, retry exhaustion
and abandoned publisher events. No source/model account or private data is used.

Two harness issues were corrected: preserve the broker's host port across restart,
and select the named error panel rather than Next.js's separate accessibility
announcer. Final runs passed; initial failures were not ignored.

## Limits

The real process-kill test uses Celery solo mode; Compose uses prefork. Browser job
states are synthetic HTTP fixtures, while backend execution uses real PostgreSQL,
RabbitMQ and Celery. This does not validate live source ACLs, ingestion, search,
cluster capacity or full document backup/recovery. The restore smoke validates
identity data and the current schema, not future document lifecycle records.

Remote exact-head CI and security checks must pass before merge; PR evidence is
recorded in PROGRESS.md and GitHub checks.
