# Architecture decision records

Record consequential choices affecting component boundaries, persistence, security, deployment, provider commitments, or expensive migrations. Routine implementation decisions need not create a record.

## Template

- Number and title
- Status: proposed / accepted / superseded
- Context and constraints
- Decision
- Alternatives considered
- Consequences and risks
- Validation evidence or required experiment
- Related specifications/task IDs
- Superseded-by link when applicable

Accepted records explain rationale. Current specifications describe current behavior. When changing a decision, add a new record, mark the earlier one superseded, and update affected specifications; do not rewrite history silently.
